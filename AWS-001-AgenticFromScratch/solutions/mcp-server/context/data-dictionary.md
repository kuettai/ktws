# Data Dictionary

Fictional quick-service restaurant chain. All data is synthetic, generated by `data/generate_seed.py`.

- Currency: USD
- Period: 180 days ending 2026-09-30
- Volume (defaults): 30 branches, 20 menu items, ~700k orders, ~2M order lines

## Schemas

| Schema | Purpose | Who can read |
|---|---|---|
| `rst` | Base tables (star schema) | Instructors / admin only |
| `mcp` | Curated views for MCP tools | `mcp_reader` role (MCP server) |

**Rule:** MCP tools query `mcp.*` views only. Never `rst.*` base tables.

---

## Curated views (schema `mcp`)

### `mcp.v_daily_branch_sales`
Grain: one row per branch per day.

| Column | Type | Description |
|---|---|---|
| `cal_date` | DATE | Business date |
| `branch_id` | INT | Branch identifier |
| `branch_name` | VARCHAR | Branch display name |
| `region` | VARCHAR | Region (state) |
| `branch_format` | VARCHAR | `mall`, `street`, `drive_thru`, `kiosk` |
| `is_weekend` | BOOLEAN | Saturday or Sunday |
| `is_public_holiday` | BOOLEAN | Public holiday flag |
| `order_count` | BIGINT | Number of orders |
| `revenue` | DECIMAL(14,2) | Sum of order totals (after discount) |
| `avg_ticket` | DECIMAL(10,2) | `revenue / order_count` |

### `mcp.v_item_sales_daily`
Grain: one row per branch per item per day.

| Column | Type | Description |
|---|---|---|
| `cal_date` | DATE | Business date |
| `branch_id` | INT | Branch identifier |
| `item_id` | INT | Menu item identifier |
| `item_name` | VARCHAR | Menu item name |
| `category` | VARCHAR | `chicken`, `burger`, `sides`, `drinks`, `dessert` |
| `qty_sold` | BIGINT | Units sold |
| `revenue` | DECIMAL(14,2) | Line revenue after discount |

### `mcp.v_hourly_sales`
Grain: one row per branch per day per hour.

| Column | Type | Description |
|---|---|---|
| `cal_date` | DATE | Business date |
| `branch_id` | INT | Branch identifier |
| `order_hour` | INT | Hour of day, 0-23 |
| `order_count` | BIGINT | Number of orders |
| `revenue` | DECIMAL(14,2) | Revenue |

### `mcp.v_channel_mix_daily`
Grain: one row per branch per day per channel.

| Column | Type | Description |
|---|---|---|
| `cal_date` | DATE | Business date |
| `branch_id` | INT | Branch identifier |
| `channel` | VARCHAR | `dine_in`, `takeaway`, `drive_thru`, `delivery` |
| `order_count` | BIGINT | Number of orders |
| `revenue` | DECIMAL(14,2) | Revenue |

### `mcp.v_inventory_daily`
Grain: one row per branch per item per day.

| Column | Type | Description |
|---|---|---|
| `cal_date` | DATE | Business date |
| `branch_id` | INT | Branch identifier |
| `item_id` | INT | Menu item identifier |
| `item_name` | VARCHAR | Menu item name |
| `category` | VARCHAR | Item category |
| `opening_qty` | INT | Units at open |
| `received_qty` | INT | Units delivered that day |
| `sold_qty` | INT | Units sold |
| `wasted_qty` | INT | Units discarded |
| `closing_qty` | INT | Units at close |
| `waste_value` | DECIMAL(12,2) | `wasted_qty * base_price` |

### `mcp.v_loyalty_tier_sales_daily`
Grain: one row per branch per day per loyalty tier (`none` = non-member).

| Column | Type | Description |
|---|---|---|
| `cal_date` | DATE | Business date |
| `branch_id` | INT | Branch identifier |
| `loyalty_tier` | VARCHAR | `none`, `silver`, `gold`, `platinum` |
| `order_count` | BIGINT | Number of orders |
| `revenue` | DECIMAL(14,2) | Revenue |

### `mcp.v_branch`
Grain: one row per branch. Reference list for resolving names to IDs.

| Column | Type | Description |
|---|---|---|
| `branch_id` | INT | Branch identifier |
| `branch_name` | VARCHAR | Display name |
| `region` | VARCHAR | Region (state) |
| `branch_format` | VARCHAR | Format |
| `opened_date` | DATE | Opening date |

### `mcp.v_menu_item`
Grain: one row per menu item.

| Column | Type | Description |
|---|---|---|
| `item_id` | INT | Identifier |
| `item_name` | VARCHAR | Display name |
| `category` | VARCHAR | Category |
| `base_price` | DECIMAL(8,2) | List price |

## Base tables (schema `rst`) — reference only

```
rst.dim_branch           (branch_id PK, branch_name, region, branch_format, opened_date)
rst.dim_menu_item        (item_id PK, item_name, category, base_price)
rst.dim_date             (date_key PK YYYYMMDD, cal_date, day_of_week, day_name,
                          week_of_year, month_num, month_name, quarter, year_num,
                          is_weekend, is_public_holiday)
rst.dim_customer         (customer_id PK, loyalty_tier, joined_date)
rst.fact_orders          (order_id PK, branch_id FK, customer_id FK NULL, date_key FK,
                          order_ts, channel, total_amount)
rst.fact_order_items     (order_id FK, line_no, item_id FK, qty, unit_price, discount)
rst.fact_inventory_daily (branch_id FK, item_id FK, date_key FK, opening_qty,
                          received_qty, sold_qty, wasted_qty, closing_qty)
```

```
dim_branch ──< fact_orders >── dim_date
                   │  └──── dim_customer (nullable: non-member orders)
                   └──< fact_order_items >── dim_menu_item
dim_branch ──< fact_inventory_daily >── dim_menu_item
```

## Gotchas

- `customer_id` is NULL for non-member orders (~40%). Views map NULL tier to `none`.
- Revenue = after line discount. There is no tax or service charge.
- Inventory is tracked per menu item (portion), not per raw ingredient. Simplification for the workshop.
- Branch IDs and item IDs match the mock API, so Redshift and API answers can be combined.
